# ConfigWright · 项目总纲

> 2026-11-10 重新立项。旧版是反面教材：不复制任何旧代码、旧文档、旧文案。

## 0. 立项基线（2026-11-10 用户拍板）

| 项 | 结论 |
|---|---|
| 开发模式 | **敏捷开发**：批次做完统一审一次，按批修，修完只复查不重扫 |
| 首版形态 | **GUI（最简）**；首版不做 CLI |
| 首版范围 | OpenCode + DSH 两个 agent；**架构不假设只有这两个**（适配器注册制） |
| 技术栈 | Electron + React + TypeScript（app-studio 选定） |
| 中心位置 | **可配置**，不绑死任何固定路径 |
| 依赖授权 | 不限；公开 GitHub、不商用；**不得引入可能给用户造成损失的技术**（读写不越界、无内核/驱动依赖、依赖优先开源可商用） |
| 数据采集 | **不采集、不上传任何数据**；无遥测、无网络请求 |
| 隐私 | 仓库与发布物中**不得出现用户绝对路径、用户名、真实配置内容**（一律占位符） |
| 安全底线 | 密钥 / 令牌 / 真实配置不得进仓库；真实配置只在本机 |
| 界面 | 用户看得懂、不出现内部黑话；尽量简单 |

## 1. 产品定位（一句话，用户原话）

**管理 rules / skills / MCP 在 agent 之间同步的软件：一个中心，简单选择哪些东西到中心里；再从中心选择哪些东西同步到哪些 agent 上。**

## 2. 为什么重来（旧版三个失败，新版验收硬线）

1. **界面看不懂** → 全文案全人话；内部术语 0 出现；一屏一个任务
2. **误报 / 滥拦挡住「应用」** → 警告不挡路；只有真的会改坏才拦；拦截必须说清楚怎么继续
3. **范围膨胀、一直用不起来** → 首版只求：中心进 → 选发给谁 → 应用 → 两个 agent 真的生效

## 3. 架构原则（AI 易维护 · 易扩展）

- **core 纯逻辑**：不 import Electron / React；UI 只做展示与调用
- **注册表驱动**：每个 agent 一个适配器文件；加 agent = 加一个文件 + 登记，**不改 UI 代码**
- **中心 = 一个可配置目录 + 一份清单**：存储格式人眼可读（JSON），无数据库依赖
- **类型即文档**：TS 严格模式；模块职责单一；命名用人话；无魔法字符串
- **写入一层显式读写模块**：所有文件改动经同一入口；写前可预览、写后可一键还原（撤销）
- **渲染进程零 nodeIntegration**；preload 只暴露白名单方法

## 4. 开发顺序（敏捷）

| 阶段 | 内容 |
|---|---|
| P0 | 立项 + 设计（信息架构 / 数据模型 / 写入安全语义 / 文案） |
| P1 | 中心管理：把本地 rules / skills / MCP 收进中心 + 中心列表与选择 |
| P2 | 分发：选目标（哪些东西 → 发给哪个 agent）+ 应用 + 撤销 |
| P3 | 收口：图标、简单引导、打包 |

每批完成统一审查（敏捷），验收跑三项：`typecheck` / `test` / `build`。测试数只增不减。

## 5. 三条当场退回（任何模式都适用）

跑不起来；密钥 / 真实配置入库；违反第 0 节基线。

## 6. 协作

- designer → `docs/design/` + 交接文档；programmer → 工程目录；reviewer → `docs/reviews/`
- 交接文档统一放 `docs/handoffs/`
- 一个文件一个 owner；app-studio 不代写

## 7. 已验证的技术事实（设计输入，来自旧版实测）

- OpenCode：递归扫描其 `<home>/skills`；`skills.paths` 可补根；`instructions` 是规则载体（JSONC）
- DSH：只扫一层，靠 `customSkillDirs` 补根；规则非单文件，必须聚合进 `AGENTS.md` 标记块；MCP 载体是 YAML patch 文件里的 `dsh-mcp-client` 条目
- 两个 agent 的配置都可能被用户或 agent 自己改写——写入必须保注释、可逐字节还原
- 旧 `D:\Code\.config\config-wright` store 含 13 个复制版 skill，新版不读、不迁移，旧件由用户自行处置
